# PDF mobile regression verification (2026-10-28)

The previous exporter used image pixels / 300 PPI as each PDF MediaBox, so different source resolutions produced different paper sizes. The SDK now centers each image on a white portrait A4 sheet, fitting both dimensions without cropping or distorting it. The preview and in-web reader use the same layout. Previously generated/shared files require regeneration; their bytes are not silently replaced.

The reported save error was reproduced with a valid JPEG containing MPF auxiliary pictures: Pillow identified it as MPO and the backend rejected its MIME. The primary JPEG is now accepted without altering the source. Regression coverage also checks all eight EXIF orientations and ensures an invalid page is identified without replacing the previous saved revision. The user's original seven source files were not provided, so MPO is a reproduced failure case, not a confirmed identification of their particular image.

Opening a PDF directly still produced a blank native viewer in the embedded test browser despite valid downloaded bytes. Mở PDF now opens a modal reader of all generated page images inside the web app, avoiding native viewer/popup support entirely. The reader scrolls independently and loads images lazily. Tải PDF prepares a server-backed saved copy when necessary, then asks for a separate direct click; it does not report that a download completed based only on a click. Native file sharing remains available independently of document save.

Verification: 630 frontend tests / 78 suites; 31 backend tests; frontend lint/build and SDK package integrity. A browser imported seven synthetic JPEGs with different sizes, landscape/portrait, EXIF and MPF; saved them, reopened the document and downloaded an actual seven-page PDF. Every MediaBox was A4 (595.28 × 841.89 pt); encoded image ratios, centering and bounds were checked using pypdf, and selected pages were visually inspected after Poppler rendering. The web reader displayed all seven pages. Physical Google app on iPhone, Safari, Android and actual camera hardware still require device verification.

Dependency audit: production dependencies report zero known vulnerabilities. The full audit reports existing dev-only advisories in Vitest mocker, undici (via jsdom) and zod (via eslint-plugin-react-hooks). These tools are used with trusted repository tests/lint input and are not shipped in the static app or backend runtime; no EventSource/network/cache API or user-supplied schemas are exposed through them. Dependency upgrades are deferred from this PDF change, with review due 2026-11-04; do not apply forced audit remediation.
